# 当前实验设计

最新速度优先策略：fast_single_pass为默认。匿名S编号贯穿看板/请求/结果，原图路径留在内部manifest。每张六组一次读取，跳过难辨小细节，标注明确主要缺陷；证据一句话，不重复检查或写长报告。默认局部补图预算0，后台有界局部看板仅在显式开启复核模式时使用。严重度允许临时视觉近似，后续迭代校准。必要的样本映射/JSON结构检查由程序一次完成。

1. GT和生成图采用统一浮点CIELAB；256像素最长边用于指标统计，原图用于看板和按需裁剪。尺寸对齐会记录在文件和算法流程中；小物体仍需原尺寸检查。
2. A保守候选使用相对彩度/相对色度结构收缩，加上交叉拟合ab(L)残差收缩与GT颜色保留比例。第八轮CV7把残余门槛2→4、结构保留拟合残差0.5→1联合调整，另24张GT的1,272例控制中误报13→0、检出143/168不变；单参数放宽被拒绝，详见第八轮报告。无彩色参考、仍保留GT颜色结构的彩度缩放不自动归A。色相集中度只进入待复核信息，不直接熔断。任何CV候选都不产生最终“已核验”。
   CV8根据主人确认增加GT参考范围：GT无有效彩色参考只评B/F，A/C/D/E1/E2不评价。10,000训练GT mean C第1百分位3.5214只给候选，不自动跳过；AI从GT确认，自然白灰场景不一概排除。compact的BF_only行对应实际两类checked_categories，scope和provenance保留排除范围，指标统计不把跳过类型作为负例。
3. D保留4×4网格、像素活动覆盖和RGB白平衡解释；第五轮在平移分支增加GT颜色分组等权共同变化、投影P25和颜色结构保留约束，减少大物体错色主导全图数字。统一曝光优先排除。按GT划分真实弱参考开发/留出，并用合成开发约束及新24张GT固定确认；详见第五轮报告。色组不是物体，CV仍只是候选。
4. C/E采用最长边512的数值连通区域导航。第七轮色相方向乘sqrt(min(C_GT,C_gen)/max(C_GT,C_gen))，降低近灰残余色度的方向噪声；原信号保留，彩度增减不变。P95紧种子、扩展框、JPEG紧框规则不变。96个灰阶/严重褪色控制的色相区域清零，512框检出233→232/240；详见第七轮报告。区域不是物体分割，真实语义精度未校准。
5. B/F未增加自动标签判定。B仍需真实边界判断，F由视觉阶段依据常识判断。
6. 看板严格每张6组，六行三列，单组GT+生成图+双向彩度差；尾张允许少于6组。第三列不是总ΔE Turbo图。共享显示尺度、方向和gamma，黑色不能证明无错色。
   色相双图/三色合成图只保留为可选实验，真实12例耗时增加，默认不采用。主人确认的C/E2规则进入提示词：主要褪色优先E2，明显换色相才标C，不因单纯褪色重复添加C。
   第十三轮测试单张Δab总色度距离，不含亮度，Turbo或单橙色显示共享已有尺度。96例配对GT/生成/遥测像素一致，Turbo墙钟235秒/原202秒，单橙色231秒/配对原209秒；均完整，未获得稳定主要物体识别收益，不设默认。原版自身标签复测65/96一致，模型波动需与显示效应分开。下一步优先A/GT参考与物体颜色grounding，详见第十三轮报告。
7. 默认视觉模型gemini-3.8-flash-high，已授权通过agy CLI直接调用。Gemini用工具自行读本地PNG，直接修改指定JSON文件；回复只作保存确认。程序读取本地文件后处理，不直接嵌入图片、不从模型回复解析标注内容。
   第六轮采用compact文件：S编号的null/数组表示未看/已完成，缺陷只填id/severity/object/description。程序补固定元数据，不编造颜色或位置，保留模型原文件，无CV类别导航。相同36例249→227秒；Medium78秒仅作模型候选。当时三路六例/150秒超时的调度未采用，详见第六轮报告。
   第八轮新24例169秒；加GT主色/A边界规则的同PNG对照218秒且出现新的误述和漏项，拒绝默认。保留原轻量提示词，未宣称GT物体颜色误述或C遗漏已解决。
   第九轮两列三行、区域框和分模型上下文均未达到速度要求，保留可选实验。新24例原六行148秒；GT无有效彩色参考的用户规则经12例实测并采用，详见第九轮报告。
   第十轮同CV8/同24例按S编号像素一致：原顺序188秒，同GT相邻223秒，两批12例顺序调用244秒；后两者仍有错漏且更慢，当时不设默认，参见第十轮报告。
   第十一轮改变调度：原样本顺序、每任务两张六组看板（最多12例）、最多四个独立agy进程/会话。48例相同四任务，二路313.28秒、四路164.31秒，全部成功，输入PNG/指标/顺序哈希一致。run_sheet_workers.py负责分区和有界调度；每任务agy_runner.py单次调用、自读本地看板、自写独立JSON，程序完整汇聚到reviews_merged.json后校验导出。默认四路可配置；不是全批共享文件或对话。模型差异仍存在，31/48标签集合与参考范围一致不是准确率。参见第十一轮报告。
8. CV→六组看板→外部视觉→结果完整性校验→不确定项解决→实验候选JSON/流包。保留源数据哈希，避免图像改变后复用审核结果。
   第十二轮根据主人反馈扩展为跨批次滚动队列：所有ready任务进入一个有界FIFO池，任务完成即补位，无轮次/批次执行屏障；各批独立完成、合并与导出，失败批次不取消其他批次。全队列成功后可汇总候选JSON/流包，来源与B/F-only范围沿用父批provenance。--workers是共享总上限；--batch支持多目录，--queue-run-id记录全队列墙钟。两个调度检查确认慢批次不挡后批导出和失败隔离，实际192例运行验证跨批次接续。
   第十二轮新96例同任务四路304.45秒、八路277.11秒；另192例同任务八路353.55秒、十六路245.70秒，均完整无失败。采用十六路作为新prepare批次默认，每任务12例不变。八路实际后批131秒启动、前批169秒结束；十六路后批189秒先导出、前批246秒才导出。完整输入与标签分歧见第十二轮报告；CV阈值没有改变。
9. 同类不同物体在过程/候选JSON中分别记录。Label Studio旧界面每类别只有一个等级，因此展示最大等级并保留逐物体描述，不能再用旧导出器反向覆盖完整逐物体候选。
10. 原始gpt_score/labeling_model/timestamp不改变。human_review.completed_by=0明确表示外部AI，不伪装真人；详细模型元数据单独放provenance，正式meta仍只保留3字段。

## 阈值与评价

训练GT分布辅助分层和搜索范围。旧标签仅探索关联。合成干预按GT ID拆分开发/留出，并使用新GT检查每次迭代；报告每种干预的错误，不能用合成F1声称真实标注精度。

A→D路由误差必须单独报告。严重度需后续真人参考案例，不由分位数直接决定。盲审应比较二图/三图/三图加摘要；正式流程仍待Antigravity协作验收。
