# 第16轮：真实图位置提示与跨划分流程检查

> 历史实验：本轮使用了现已取消的下游GT资格/排除路径。以下观察与模型原文件保留，不代表CV10新阶段边界已验证；新流程须重新prepare。原报告逐字节快照存于docs/archive/stage_boundary_20261013/before。

2026-10-13完成。训练/测试各12个新GT、两模型各24对，共24 GT、48真实图像对；两条件96次逐图观察。未采用新增位置提示，默认仍CV9的短A/E2证据，数值阈值不变。

## 设计与证据边界

应用57张冻结弃用清单，排除已用于此前CV/缺陷诊断的GT。按GT颜色结构丰富、低彩度、颜色集中及固定随机控制四层，各划分每层3 GT。GT预筛可能已看过部分GT，不能说整个项目从未见过。

两条件看板SHA、CV、顺序、High模型、每任务2张看板一致。候选仅加一句：“在GT与生成图的同一位置对应同一个物体，再写颜色差异。GT颜色只写看得到的，不凭物体常识补色；优先明显受损的主要物体，别把相邻物体或局部灯光的颜色写成该物体自身颜色。”配置在[object_round16_config.json](../../experiments/cv_workflow/archive/rounds_15_16/object_round16_config.json)，默认config未开启它。

读取结果前，Codex从固定六组看板记录12 GT/24模型对的明显颜色/位置锚点，保存在运行内grounding_reference_before_results.json，不提供给Gemini。它是AI看板诊断，不是人工金标准，不用细微白/米色差异计算准确率。

48对中14对类别集合/范围变化；严重度差异不用于判断质量。典型诊断：

- 消防栓GT绿顶、黄柱、银灰接口，两条件仍笼统写“GT绿色消防栓”，没有解决多部位颜色概括。
- test S018下方Norfolk牌生成图黄褐色，基线误述为蓝色，候选写浅黄色；该例有所改善。
- test S021候选把GT灰阶树叶写成“自然深绿色”，仍存在常识补色。
- train S004候选把明显银灰→土黄的前景车放行；test S004候选漏掉中间灰白→黄绿衬衫，而基线有记录。
- test S008候选从天空E2改判A，近灰图片的局部残色问题仍在。

故不把“缺陷变少”当作改进，不采用位置提示。下一步优先物体部位/局部颜色的最小CV证据，而不是继续堆一般性提醒。

## 本轮暴露的流程问题与修正

初始8个原生调用中7个写齐结果；1个CLI返回SUCCESS却留下12个null。另3个已写齐的测试任务在导出时因源记录缺少labeling_model报错。保留日志/实际文件，只对null任务新建同输入尝试，追加1次High调用；最终96个观察全部覆盖，0uncertain。三个已写齐文件由程序重新后处理，未重跑视觉。

测试源任务本来就是未打分桩：gpt_score=null，且无旧模型名/时间戳。新流程检测到这种输入后保存完整visual_reviews.json及source_metadata_pending.json，状态observations_saved_without_source_scores；不再让模型成功被算作导出失败，不填造原评分/元数据。旧严格reviewed_candidate格式暂不导出。训练两条件候选Schema通过，测试是完整标签观察，不能称正式候选/交付。

GT范围也有一个待解决冲突：train 000000371701在第14轮G0408独立GT看板明确keep，图像SHA未变；本轮两条件S017均声明黑白GT，与同GT另一模型行及预筛不一致。57张冻结清单未更新，模型原文件未改，训练22条候选只作诊断，不称新清洁交付。下一步应传递已独立确认的GT状态，减少重复检查及上下文误排；不靠单一低彩度阈值改变GT结论。

## 时间与用量

初始8任务共享队列313.75秒；训练基线311.45秒、位置313.75秒，未显示速度优势。测试发生恢复，不能把恢复汇聚的几秒当完整视觉耗时；额外12例调用143.09秒，准备/诊断停顿另计，未构造无效的测试速度排名。

共9次原生调用，CLI均SUCCESS，但其中1次无有效标注，说明必须看实际文件。完整调用含失败用量在native_usage_all_attempts.json；原初始queue_result只统计当时成功走完主机后处理的调用，不能独自作为全轮用量。
