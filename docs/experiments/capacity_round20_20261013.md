# 第20轮：固定并发容量确认与最小位置提示

2026-10-13，已完成。基线CV11、新A契约、High、compact、fast_single_pass；上游57张GT冻结清单复用，下游只评价生成图七类。

## 本轮设计

容量条件每任务4/8张，使用相同192输入、32张六组看板及顺序，实际并发上限同为4。4张条件8个24样本任务，滚动补位；8张条件4个48样本任务。分别运行计时，不混跑条件。它是固定四路的诊断，不能直接证明十六路生产吞吐。

84张此前未进入实验的val GT，两模型168真实输出；其中6个GT另生成灰阶、统一有色、20%留色及局部留色各一张，共24控制。控制插入全队列；只冻结A真值，其他类别不造人工真值。共192独立输入，重复条件不算新样本。

容量对照之后固定8张/任务、四路，单独试每S最多一个色相差候选中心。沿用现有区域候选及排序，不改阈值；取紧凑种子框中心x/y百分比，无候选不提供。它只定位数值差异，不命名物体、不决定C。185/192输入有候选，默认不开启。

模型自己只读所列本地看板，直接改各任务reviews_gemini.json，不发送图片、不返回标签JSON、不查原图。只从实际文件判完成。300秒限时保持；失败及新尝试单列，已有完整标签不重跑。

## 本轮落实的主机修正

所有17调用完成后才修改agy_runner：当CLI ERROR但本轮实际JSON已写齐并通过覆盖/Schema/A唯一性检查，直接导入；保留native_status/native_error及file_completed_despite_native_error。null/无效文件仍未完成，不从回复猜标签，不把null改为[]。真实实验使用修改前运行器，所以修正没有混入容量/坐标计时。

16项workflow检查＋9项runner检查通过；用保留现场重放4个完整ERROR文件均接收，1个EOF null及第19轮SUCCESS空文件均拒绝，共6现场重放、0新模型调用。后处理工具recover_file_results.py可恢复旧完成文件，原native错误/用量记录保留。

## 采用标准

优先有效完成样本/墙钟分钟，结合已知A控制和明确主要错色诊断。标签数量、两次集合一致性、Schema通过不等于准确率。容许少量不完美；如容量大幅提速且无明显主要缺陷系统性损失，可更新默认。位置提示单独决定，不因更长提示产生更多标签就采用。
