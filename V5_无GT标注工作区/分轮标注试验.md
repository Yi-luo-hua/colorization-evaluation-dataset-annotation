# V5 分轮标注试验

40 张人工对照图分成 8 包，每包 5 张。用全新的匿名 PNG 任务从图像标注，人工参照留在主控目录，公开任务只提供匿名生成图、本轮提示和相关模型结果。默认模型为 Gemini 4 Hydrogen High。每条消息都附原始七类定义、关系与等级、B/C/F 判空提醒、绝对文件路径和虚构结果 JSON 示例。

1. 第一轮检查 D/A/B。
2. 第二轮检查 C/E1/E2/F，读取第一轮普通结果 JSON。
3. 第三轮在新会话先完成七类独立观察。验收后在同一会话发前两轮的普通结果 JSON，提交最终七类结果。

结果只包含 S 编号及对应的缺陷数组，缺陷字段为 id、severity、object、description。空数组表示本轮已检查且无确认命中。null 可以保留待处理，但不能作为完成结果。验收核对任务身份、结果、成功读图及必要 JSON 的原生回执。各轮结果和回执独立留档。运行完成后生成 comparison.json，单列 17 张已裁决与 23 张待核对稿，并汇总 40 张。

运行入口为 split_pass_pilot.py。参数 --source-root 指向保存人工合并 JSON、图片和 Windows 浏览器拦截程序的原工作区，--run 指向私有日志与结果目录，--packets 指向单独的匿名任务目录，--agy 指向 Antigravity CLI。加 --prepare-only 可先生成任务文件。相同目录、相同模型重新启动时，程序承接验收记录及原会话。明确额度耗尽时停止后续模型调用并保留现场。

## 每会话图数对照

split_pass_pilot.py 的 --batch-size 支持 5、10、20。用 split_pass_benchmark.py 对比 10 张和 20 张。两个条件都使用相同 40 张、固定随机顺序、同一模型和相同并发上限，分开运行。第三轮两条消息均复核标签等级。只要初稿或盲查为空，或终审拟判空，就复扫整张图和全部七类。

benchmark.json 在每组结束后记录从执行器启动到终标汇总的墙钟耗时，另列调用次数、原生请求、成功读图、输入与缓存读取、输出 token 及执行覆盖情况。独立的原生 /usage 查询记录账号剩余百分比，截图界面的显示精度和额度刷新会限制两次快照之差的解释。该计量和每个请求的 token 分开保存。
